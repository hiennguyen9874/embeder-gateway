# Domain docs

This repo uses a single-context layout: root `GLOSSARY.md` and `docs/adr/`.

Before exploring, read `GLOSSARY.md` and any ADRs in `docs/adr/` relevant to the area. If they do not exist, proceed without suggesting their creation upfront; domain modeling creates them when terms or decisions are resolved.

Use the glossary's vocabulary in output, including issues, proposals, hypotheses, and test names. If a concept is missing, reconsider the term or note the gap for domain modeling.

If a proposal contradicts an ADR, explicitly identify the conflict and why the decision might be reopened.
